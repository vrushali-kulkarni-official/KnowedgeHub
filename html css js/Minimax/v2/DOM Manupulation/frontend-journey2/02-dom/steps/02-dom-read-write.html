Reading and writing what is on the page

Three properties do most of the talking: textContent for text, innerHTML for HTML inside, and value for what the user typed.

The idea

const h1 = document.querySelector("h1");

h1.textContent          // READ: the text inside it
h1.textContent = "New"  // WRITE: replaces the text

h1.innerHTML            // READ/WRITE: the HTML inside it

const input = document.querySelector("input");
input.value             // what the user has typed right now

Each one is a different door into the same element:

  • textContent — plain text only. Tags in the string come out as literal characters. This is your default tool.
  • innerHTML — real HTML. If you write "hi" into it, you get bold text. If the string came from a user, that is a security hole (more on that in Act 3).
  • value — only for <input>, <textarea> and <select>. This is the live value the user is editing.

Also worth knowing: textContent is fast and safe. innerText exists too but it depends on layout (it reflects what is visually visible) which makes it slow and surprising. Use textContent.

The rule that saves you from bugs

Read with textContent, write with textContent, unless you genuinely need HTML inside.

Why? innerHTML re-parses the string as HTML every single time you set it. That is slower, it wipes out any event listeners you attached to the children, and it opens the door to XSS.

Python &#8594; JavaScript

Same job, different tool.

Python (bs4)
text = h1.get_text()
h1.string = "New"
→
JavaScript (DOM)
const text = h1.textContent;
h1.textContent = "New";
Python (raw html)
html = h1.decode_contents()
→
JavaScript (raw html)
const html = h1.innerHTML;
Python (form value)
value = request.form["name"]
→
JavaScript (form value)
const value = input.value;
