Removing and replacing elements

Things have to be able to leave. Learn to delete an element, swap one for another, duplicate a row, and wipe a whole container.

The idea

el.remove();                 // delete it
el.replaceWith(other);       // swap it for something else
el.replaceChildren(a, b, c); // replace all its children
el.innerHTML = "";          // wipe the inside (leaves el itself)

const copy = el.cloneNode(true);  // duplicate (true = with children)
el.after(copy);                   // put the copy next to it

The difference between remove() and innerHTML = "" is worth being precise about:

  • el.remove() deletes the element itself from its parent.
  • el.innerHTML = "" deletes everything inside it, but el stays.

cloneNode(true) copies an element with its children; cloneNode(false) copies only the empty shell. The copy is detached until you insert it.

One warning about innerHTML = "": it destroys every child element, including any listeners you attached to them. If you have a row with a click handler and you wipe the list with innerHTML = "", the handler is gone. That is exactly why the state-and-render pattern from the last step uses render() — it rebuilds everything from scratch each time.

Why removing things is a skill, not a detail

Two real reasons to get good at this:

  • Memory. A removed element that is still referenced somewhere keeps its listeners and data alive. Remove it properly and let it go.
  • Correctness. If you delete a row from the screen but not from your data array, the next render brings it back. Delete from the data, then render.
