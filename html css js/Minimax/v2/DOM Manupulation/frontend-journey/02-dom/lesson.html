Act

DOM manipulation

Nine steps of pure DOM work: find elements, read and write them, build them, style them, delete them, listen to them, and keep your data straight.

What you will build up to

    ['Find any element with CSS selectors you already know.', 'Read and write text, HTML and form values safely.', 'Create, insert, duplicate and delete elements.', 'Manage classes, attributes and data attributes.', 'Handle clicks, form submits and keystrokes with event delegation.', 'Keep state in JavaScript and render the DOM from it — the React mindset.']

Steps in this act

  1. Finding elements: your CSS selectors, now useful
    You already know CSS selectors. Now they become a way of finding things on the page and holding on to them.
  2. Reading and writing what is on the page
    Three properties do most of the talking: textContent for text, innerHTML for HTML inside, and value for what the user typed.
  3. Building new elements
    So far we only changed things that already existed. Now we make new ones. It is always a two-step dance: create the element, then insert it.
  4. Removing and replacing elements
    Things have to be able to leave. Learn to delete an element, swap one for another, duplicate a row, and wipe a whole container.
  5. Attributes, classes and inline styles
    Changing text is only half of it. Often you need to change how an element looks or what it means to a screen reader. Three tools: attributes, classList, style.
  6. The innerHTML trap (and how to stay safe)
    A short, important detour. This is the one rule that separates a working page from a vulnerable one.
  7. Walking the tree: parents, children, siblings
    Sometimes you do not know the selector — you only know where the click happened. The DOM gives you ways to move up, down and sideways.
  8. Event delegation, forms and the keyboard
    Three practical event patterns: listening on the parent instead of every child, handling form submit without reloading the page, and reacting to Enter.
  9. Data first, DOM second
    The mindset shift that separates hobby DOM code from professional front-end code. Keep the truth in JavaScript, and let the DOM be a picture of it.
