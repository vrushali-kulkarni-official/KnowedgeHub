Event delegation, forms and the keyboard

Three practical event patterns: listening on the parent instead of every child, handling form submit without reloading the page, and reacting to Enter.

1. Event delegation

Clicking a button makes the event travel up the tree, from the button to its parent, to its grandparent, all the way to document. This is called bubbling.

So you can listen on the parent once, and catch clicks on every child:

list.addEventListener("click", function (event) {
  const item = event.target.closest("li");
  if (!item) return;          // clicked something that is not an li
  item.remove();
});

Why bother? Three reasons:

  • One listener instead of fifty. Cleaner and faster.
  • It keeps working when new children are added later. If you attached a listener to each <li>, a new <li> would have no listener.
  • It is exactly what React does under the hood — one listener at the root.

event.target is the element clicked. event.currentTarget is the element you attached the listener to. With delegation you need both: target to know what was clicked, and you already know currentTarget because it is the parent you attached to.

2. Forms

A form has a special submit event. By default the browser sends the data to a server and reloads the page. For a single-page app you do not want that.

form.addEventListener("submit", function (event) {
  event.preventDefault();          // stop the page reload

  const text = form.querySelector("input").value;
  // ... do something with text
  form.reset();                    // clear the fields
});

Two details that trip everyone up:

  • Without preventDefault(), the page reloads and your JavaScript state is gone.
  • The submit event fires when the user presses Enter in a text field too, not only when they click the button. So you get Enter for free.

Also useful: form.elements.nameInput.value to read a field by its name attribute. That is the classic way to read form data.

3. The keyboard

input.addEventListener("keydown", function (event) {
  if (event.key === "Enter") {
    // act
  }
  if (event.key === "Escape") {
    // cancel
  }
});

event.key is the key that was pressed ("Enter", "a", "ArrowDown", "Escape"). event.key is the character; event.code is the physical key ("KeyA"). For text input, use event.key.

input vs change: "input" fires on every single keystroke. "change" fires when the value is committed (blur or Enter). For a live search box, use "input".

Wait, when does my script run?

Here is a real problem. If your script is in the <head>, it runs before the body exists, so document.querySelector("#app") returns null.

Three ways to fix it:

// 1. Put the <script> right before </body>  (simplest)

// 2. Use the DOMContentLoaded event
document.addEventListener("DOMContentLoaded", function () {
  // everything is ready now
});

// 3. async / await at the top of a module
// (you will meet this when you meet npm)

Option 2 is the habit to build, because it survives being moved into a separate .js file later. And in a real app, your script usually lives in a separate file — in which case option 2 (or defer on the script tag) is the only option.
