Setup & Orientation

Everything you need, nothing you don't. Fifteen minutes, once.

You already know how to program. What you're missing isn't a compiler or a package manager — it's the environment and the mental model of the browser. So Act 0 is short on purpose: one step, one habit.

The one habit that matters: keep DevTools open in a side panel, permanently, from now on. Frontend development is a feedback loop of change → see → inspect → change. DevTools is the second half of that loop.

0.1 — Your Toolkit

Get a working editor + browser + DevTools loop, and understand the four DevTools panels you'll actually use.

You need exactly three things:

  1. An editor. VS Code is the free standard. Nothing in this course is VS Code specific, so if you already use something else, keep it. Two extensions worth having: Live Server (right-click → "Open with Live Server" to serve your files over http instead of file://) and Prettier (auto-formats your HTML so you never fight indentation).
  2. A browser. Chrome or Edge, because DevTools comes built in. F12 on Windows/Linux, ⌥⌘I on Mac.
  3. Nothing else. No npm, no bundler, no server. For the first several acts you open a .html file and it runs. That is not a simplification — it is how the web actually works, and understanding that is part of the course.

The four panels

PanelWhat it answers
Elements"What is the DOM right now?" — the live tree your HTML became, and what CSS is applied to the selected node.
Console"What is my JavaScript saying?" — errors, logs, and a live JavaScript REPL you can type into.
Network"What went over the wire?" — every request, its status, headers, body, and timing.
Application"What is stored on this machine?" — cookies, localStorage, IndexedDB, service workers.

You'll spend most of your time in Elements and Console. The other two come into their own in Acts 8 and 9.

A trap to avoid: opening the file via file:// and then wondering why fetch() refuses to work, or why modules won't load. Browsers apply extra security rules to local files. When a lesson needs a server, it says so and tells you how to start one.

What to notice

  • DevTools' Elements panel shows the DOM after the browser has parsed it — which is not always identical to your source file.
  • The Console doubles as a REPL: you can type JavaScript there and evaluate it instantly against the current page.

Challenge — Get the loop working

  1. Open this file in Chrome/Edge with F12 open on the right side.
  2. In the Console, run document.querySelectorAll('p').length — what does it tell you, and why might it differ from the number of <p> tags in the source file?
  3. Right-click a paragraph → Inspect. In the Elements tree, use the small </> icon to expand a node and see its children.
  4. Create a new file scratch.html next to this one with a <h1> and two <p> tags, open it, and repeat the exercise. Now you can build your own feedback loop.
Stuck? Open the hints
  • document.querySelectorAll returns a live collection of every element matching the selector in the current DOM.
  • If the counts differ, the browser probably added or removed an element while parsing — which is exactly what Act 1 Step 1.4 is about.
