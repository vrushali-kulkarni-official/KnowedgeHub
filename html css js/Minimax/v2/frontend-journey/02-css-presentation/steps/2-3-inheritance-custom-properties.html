Inheritance & Custom Properties

Control how properties flow down the tree, and build themable values with CSS variables.

What to notice

  • Custom properties are resolved at use time, not at definition time. If --brand changes on an ancestor, everything using var(--brand) below it updates instantly.
  • var(--x, fallback) provides a fallback value if the variable isn't defined — worth using for safety.

This box's colours come from three custom properties. Change one variable and everything using it updates at once.

Challenge — A themeable card

Build a card that works in both light and dark mode using only custom properties:

  1. Define --card-bg, --card-fg, --card-border and --accent in :root.
  2. Add a class .dark that redefines those four variables.
  3. Style the card using var() only — no literal colours anywhere in the card rule.
  4. Add a button that toggles the .dark class. (Hint: Act 4 has the JavaScript, but you can also do it with a tiny inline onclick just to see the effect.)

Now change --accent in one place and confirm every accent in the card updates. That's the payoff.

Stuck? Open the hints
  • You need three variables, not one: the card's own background is different from the page's background, and in dark mode both change.
  • If a child element ignores your variable, check whether you're redefining the variable on the card instead of on :root — variables resolve from the element they're used on, walking up.
