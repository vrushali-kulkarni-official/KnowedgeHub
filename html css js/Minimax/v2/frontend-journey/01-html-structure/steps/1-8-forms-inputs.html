Forms & Inputs

Learn the form vocabulary — this is the part that directly feeds your API, form-submit and file-upload work later.

What to notice

  • A <label> can wrap its input instead of using for — both work, but for/id is easier to reuse.
  • required, min, max, pattern, step give you browser-native validation for free. You can style it with :invalid and :user-invalid.
  • placeholder is a hint, not a label. It disappears the moment the user types — never use it as the only label.

Live demo — a real form




Try it: click the label text and watch the input focus. Then press Tab a few times — focus moves between real controls only. Then try submitting with an empty required field.

Challenge — A signup form, done right

Build a signup form with these requirements, using no class attributes (you haven't learned CSS yet, so semantics and attributes are all you need):

  • Name — text input, required
  • Email — email input, required
  • Password — password input, required, minlength="8"
  • Country — a select with 3 options, one preselected
  • A "newsletter" checkbox, unchecked by default
  • A submit button labelled "Create account" and a second button that must not submit the form
  • Every input has a proper <label>

Extra credit: add a hidden input called signup_source with the value landing-page, and explain what it's for.

Stuck? Open the hints
  • The second button needs type="button" explicitly.
  • The hidden input is for data your JavaScript or server needs but the user doesn't have to see — the same trick a real app uses for a CSRF token.
