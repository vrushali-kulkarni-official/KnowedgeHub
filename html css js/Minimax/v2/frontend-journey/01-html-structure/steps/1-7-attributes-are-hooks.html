Attributes Are Hooks

Understand id, class and data-* as the interface that CSS and JavaScript will grab onto.

What to notice

  • class values are space-separated: class="btn primary" is TWO classes, not one class with a space in it.
  • A data-* attribute name must be lowercased and hyphenated in HTML: data-user-id becomes el.dataset.userId in JS (camelCase automatically).

Live demo

Every element on this page is inspectable. Pick one in DevTools → Elements and read its class, id and data-* attributes. Then look at the Styles panel and see which CSS rules matched it.

This is the loop: HTML names things → CSS styles by name → JS finds them by name. All three speak the same vocabulary.

Challenge — Name things like you'll find them in six months

Below is a page written with meaningless names. Rewrite the attributes so that:

  • every id is unique and describes what the thing is
  • every class describes a role or a style, and can be reused
  • at least one element carries a data-* attribute holding a piece of data that JavaScript would need (an id, a price, a status)
<div class="a" id="x1">
  <div class="b" id="x2">Buy Now</div>
  <div class="c">$49.00</div>
  <div class="d" id="x3">Add to cart</div>
</div>

Then explain in one sentence each: which is the id a JavaScript developer would look up, and why is the price a data-* rather than an id?

Stuck? Open the hints
  • One element, one id. If you need to identify two different product cards, that's a data-* (like data-product-id="123"), not two ids.
  • Classes are for reuse: two buttons that look the same share class="btn" even if their ids differ.
