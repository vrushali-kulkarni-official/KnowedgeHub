Headings, Lists & Text Semantics

Use the text-level elements correctly, and keep your heading outline valid.

What to notice

  • <code> and <pre> are two different things: <code> styles a run of code inline; <pre> preserves whitespace and line breaks (and combines with <code> for a code block).

Challenge — Fix the outline

Here is a document with a broken heading outline and mis-used text elements:

<h1>Blog</h1>
<h4>Latest post</h4>
<p>Published <em>today</em> by <strong>Ana</strong></p>
<h2>Latest post</h2>
<p>Read the <span style="font-weight:bold">full article</span> for details.</p>
<h3>More posts</h3>
  1. Rewrite it with a valid heading outline (one h1, then descend one level at a time).
  2. Replace every appearance-driven element with a meaning-driven one.
  3. Turn the final list of "more posts" into a real <ul>.
  4. Add a <time> element for "today" with a proper datetime attribute.
Stuck? Open the hints
  • A heading level should reflect the document's outline, not the font size. Both "Latest post" headings are the same kind of thing, so they should be the same level.
  • <time datetime="2026-10-22">today</time> — the attribute holds the machine-readable value, the text holds the human-readable one.
