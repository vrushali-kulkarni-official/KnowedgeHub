Runtime

`Runtime` is a convenience object that bundles run-scoped context and other runtime utilities.
It is injected into **graph nodes and middleware**

Runtime object provides access to:

def my_node(state, runtime: Runtime[Context]):
    user_id = runtime.context.user_id

This is essentially **dependency injection for graph execution**.

def get_profile(runtime: ToolRuntime) -> str:
    """Get the current user's profile."""

Store

def get_preferences(

ToolRuntime field #6 — `stream_writer`

stream_writer

runtime.emit_output_delta(...)

Rather than waiting until the tool completely finishes, the current runtime API exposes `stream_writer` as part of Runtime, and ToolRuntime receives a tool-specific stream writer.


Why streaming matters for agents?

1. Search 50 documents
2. Query database
3. Call ServiceNow
4. Call Salesforce
5. Combine results

Without streaming:

User
  │
  │ wait...
  │ wait...
  │ wait...
  ▼
final answer


With progress/output streaming:

User
  │
  ├── Searching...
  ├── Found 20 documents
  ├── Checking ServiceNow
  ├── Checking Salesforce
  └── Completed

| --- | --- | --- |

| `store` | Yes | Yes |
| `stream_writer` | Yes | Yes |
| `state` | Not part of Runtime object | Yes |
| `config` | Not part of Runtime object | Yes |
| `tool_call_id` | No  | Yes |
| `tools` | No  | Yes |
| `execution_info` | Yes | Yes |
| `server_info` | Yes | Yes |
| Tool-specific | No  | Yes |

Checkpointer
checkpointer persists the state of a graph 
across execution steps and runs, keyed by thread


Run 1 → save
Run 2 → load previous state


agent
  ↓
approval required
  ↓
pause
  ↓
checkpoint
  ↓
human approves
  ↓
resume



InMemorySaver

checkpointer = InMemorySaver()

graph = builder.compile(
    checkpointer=checkpointer
)


PostgresSaver

with PostgresSaver.from_conn_string(DB_URI) as checkpointer:
    checkpointer.setup()

    graph = builder.compile(
        checkpointer=checkpointer
    )

ShallowPostgresSaver
