The 30-second version

What are these things?

Two ways of using AI to write code. Same goal, different roles for you.

🎨

Vibe Coding

You drive, AI types. You describe what you want, AI writes the code, you review and guide. You're the architect, AI is the fast junior. Coined by Andrej Karpathy in Feb 2025.

🤖

Agentic AI Coding

AI drives, you tech-lead. You give high-level goals, the AI plans, writes, tests, and fixes its own bugs. You review the result. 5-10x productivity when done right.

⚡

The Pro Move

Use both. Vibe for architecture and risky bits. Agentic for boilerplate, refactors, and tests. Switch based on task clarity and risk.

The most important skill

The "New Feature" prompt template

The more you specify, the less the AI has to guess. This is the template pros use.

# Context I'm building DocuMind AI, a FastAPI + PostgreSQL SaaS for chatting with PDFs. The existing code has: User model, JWT auth, /api/v1/users endpoints. PostgreSQL via SQLAlchemy 2.0 async, Alembic for migrations. # Goal Add a /api/v1/documents endpoint that lets users upload PDFs. # Constraints - Use the existing User model and auth dependency - Store files in /uploads/{user_id}/{doc_id}.pdf - Save metadata to a new Document model (id, user_id, filename, size, uploaded_at) - Use python-multipart for file uploads - Don't add new top-level dependencies - Follow the same patterns as the existing /users router # Acceptance criteria - ☐ POST /api/v1/documents accepts a PDF, returns 201 with the document - ☐ GET /api/v1/documents returns the user's documents - ☐ DELETE /api/v1/documents/{id} removes file and metadata - ☐ Returns 401 for unauthenticated, 404 for wrong user - ☐ pytest tests for the happy path and the auth failure

Compare this to "Add a documents endpoint" — and you'll see the difference immediately.

The daily loop

How pros actually use AI to code

Same loop, every feature, every day. 5 steps, one habit.

🧠

1. Understand

2-5 minutes. What behavior do I want? What does "done" look like? What could go wrong? How will I test it?

📝

2. Spec

5-15 minutes. Write the spec. Use the templates. The more specific, the better. AI is a junior; juniors need clear tasks.

✨

3. Generate

Pick the right tool. Tab-complete for tiny, chat for small, agent for medium+. Go get coffee while the agent works.

👀

4. Review

Skim 90%, deep-read 10% (auth, security, money). Run the tests. Trust the behavior, not the syntax.

🔄

5. Iterate

Tell the AI what's wrong. Be specific. After 3 failed attempts, take over. Commit, push, repeat.

The launch checklist

Before you ship anything

If you can't tick all of these, you're not ready to launch. The good news: each one is small.

Code Quality

All tests pass (`make test`)
No linter errors (`make lint`)
No type errors (`mypy app`)
Coverage >80% on services and API
No secrets in code (only in env vars)
All dependencies pinned in requirements.txt

Security

All endpoints require auth (except /health, /auth/*)
Passwords are hashed (bcrypt, not MD5)
JWT tokens have expiry
CORS is configured (not `*`)
File uploads have size and type limits
SQL queries use SQLAlchemy (no string concat)
User data is filtered by user_id (multi-tenant safety)
.env is in .gitignore
Dependencies scanned for vulnerabilities

Performance

DB queries have indexes on frequently-filtered columns
LLM calls have max_tokens set
LLM calls have timeouts
Expensive operations run in background
Rate limits are set on expensive endpoints

Observability

Structured logging (structlog) configured
LLM calls traced (Langfuse)
Errors tracked (Sentry or similar)
Uptime monitoring set up
Health check endpoint works
Token usage and cost logged

Operations

Database backups configured
Secrets stored in env vars
CI runs on every PR
Deployment is automated
Rollback plan documented
